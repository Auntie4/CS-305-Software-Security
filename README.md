# CS-305-Software-Security
CS 305 Software Security
# Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?
Artemis Financial is this company that offers tailored financial plans, covering everything from insurance to investments and retirement planning. They were looking to give their software a makeover so they could keep their clients' sensitive financial info safe and up to date with the best security practices.
My main goal was to tackle any weak spots in their web application, clean up any dodgy code, and set up a solid cryptography system to make sure the data stayed secure whether it was being sent around or stored.
# What did you do well when you found your client’s software security vulnerabilities? Why is it important to code securely? What value does software security add to a company’s overall well-being?
I think I did good at the codebase by mixing automated tools and hands-on code review. This combo helped me pin down where data flows, find injection points, and catch weak encryption methods that some automated tools might miss. Coding securely is key because it helps nip risks in the bud before we go live, which means fewer chances of vulnerabilities sneaking into production. This approach shrinks the application's attack surface, making it less likely for attackers to succeed, and helps dodge major issues like data leaks, financial hits, or legal trouble.
Plus, good software security is a win-win. It keeps customer trust intact, protects sensitive business info, and makes sure we’re following regulations. By keeping our application secure, a company can safeguard its reputation, avoid painful financial fixes, and stand out as a reliable partner in the industry.
# Which part of the vulnerability assessment was challenging or helpful to you?
Tackling those complex dependency trees to fix version conflicts without messing up the app features was definitely the toughest yet most rewarding part of the assessment. Upgrading vulnerable libraries safely was a bit of a headache, but I learned a lot about managing software composition and keeping a secure package baseline without losing any core functionality. 
# How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?
To boost security, I added a layered approach by upgrading our transport layer security to HTTPS/TLS, making sure we have strict input validation, and using some solid cryptographic hash functions like SHA-256 with salting for data verification.
# How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?
To make sure my refactored app was both working well and secure, I used a mix of static application security testing (SAST), dependency check tools, and some focused unit tests. After I did the refactoring, I ran the automated vulnerability scanners again and compared the results to my initial reports. That way, I could confirm that I hadn't accidentally added any new security issues or broken anything.
# What resources, tools, or coding practices did you use that might be helpful in future assignments or tasks?
In future projects, I plan to continue utilizing industry-standard tools like OWASP Dependency-Check for continuous monitoring of software composition analysis, SonarQube for automated static code analysis, and the NIST Risk Management Framework to help me categorize vulnerabilities and prioritize mitigation techniques based on potential business impact.

From this assignment, I would proudly show future employers my Vulnerability Assessment Report and the Refactored Code Repository. This work directly demonstrates my professional ability to take an existing, insecure codebase, systematically audit it against modern security standards, apply defensive programming techniques, and successfully deliver a verified, hardened software solution.
